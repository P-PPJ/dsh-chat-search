## 写作要点（比模板更重要）

1. **截图放最前面**。放文末等于没有。
2. **对比表只用能验证的差异**。「更快」「更好用」没人信。
3. **限制必须写**。收录审核打回的第一大原因就是夸大；用户踩到没写明的限制，也会变成 issue。
4. **安装段按前置条件分组**，不要混成一坨：谁能直接装、谁需要 Git、谁需要网络。
5. **报错对照表抄原文**。用户会直接搜那段乱码，搜到就能自己解决。
6. **中英双语**。目录要求 `description.en` 必填，维护者也会读英文版。
7. 截图里不要出现私人对话内容——只截插件自己的面板，或者用中性示例。
